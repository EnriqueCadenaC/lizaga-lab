# Lizaga Lab — primer prototipo

Landing page estática en HTML, CSS y JavaScript, preparada para GitHub Pages.

## Estructura

- `index.html`: contenido, metadatos SEO y datos estructurados iniciales.
- `css/styles.css`: diseño responsive.
- `js/main.js`: menú móvil y año automático.
- `assets/img/logo-lizaga-lab.jpg`: logotipo compartido para el proyecto.

## Ver localmente

Abre `index.html` en un navegador. Para una vista más fiel, también puedes usar la extensión Live Server de Visual Studio Code.

## Publicar en GitHub Pages

1. Crea un repositorio llamado `lizaga-lab`.
2. Sube el contenido de esta carpeta a la raíz del repositorio.
3. En GitHub, abre **Settings → Pages**.
4. En **Build and deployment**, selecciona **Deploy from a branch**.
5. Selecciona la rama `main` y la carpeta `/ (root)`, y guarda.
6. GitHub mostrará la URL pública cuando termine la publicación.

## Fotografías pendientes

Los espacios fotográficos son placeholders visuales. Cuando estén listas las fotografías reales, guárdalas en `assets/img/` y sustituye los bloques `.photo-placeholder` del HTML por etiquetas `<img>` con textos `alt` descriptivos.

Nombres sugeridos:
- `hero-laboratorio.jpg`
- `fachada-lizaga.jpg`
- `recepcion-lizaga.jpg`
- `area-laboratorio.jpg`
- `equipos-diagnostico.jpg`

## Antes de publicar en producción

- Confirmar con el laboratorio todos los servicios, horarios y condiciones.
- Confirmar que el teléfono y el enlace de WhatsApp son correctos.
- Revisar que las fotografías tengan autorización y no muestren datos de pacientes.
- Añadir el dominio definitivo en `canonical`, Open Graph y sitemap cuando se decida.
- Validar los datos estructurados y la ficha de Google Business Profile.
- Añadir aviso de privacidad y la información legal que corresponda.
- Probar todos los enlaces y el sitio en distintos tamaños de pantalla.

Este prototipo no sustituye una revisión final del cliente. Los textos de servicios son informativos y no constituyen consejo médico.
